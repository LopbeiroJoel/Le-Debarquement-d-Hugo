# Armes de Hugo — plan de construction

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **Ici :** Thomas écrit le code lui-même, guidé par Claude (questions, squelettes à trous, relecture sur son Mac). Claude ne code pas à sa place.

**Goal :** Hugo porte une arme parmi 5 (carabine, PM, mitrailleuse, fusil à pompe, lance-flammes), obtenue par une carte du menu de niveau, et ses améliorations s'appliquent à toutes les armes.

**Architecture :** classe abstraite `Weapon` (package `hugo.weapon`) avec une méthode `fire` qui renvoie la liste des balles ; une sous-classe par forme de tir. Les stats de tir de Hugo deviennent des multiplicateurs (base 1) appliqués aux valeurs de l'arme. Les armes s'obtiennent par `WeaponUpgrade` (menu) ou `player.equipWeapon(...)` (coffres de Joël).

**Tech Stack :** Java 25, libGDX 1.14.2, Gradle ; tests = classes `main` avec `check(...)` comme `TestsMonde`, lancées par une tâche Gradle.

**Spec :** `docs/superpowers/specs/2026-11-13-weapons-design.md`

## Global Constraints

- Une seule arme portée à la fois ; en prendre une remplace l'ancienne.
- Les constructeurs actuels de `Projectile` ne changent pas (les mobs tireurs de Joël les utilisent).
- `ATTACK_DAMAGE`, `FIRE_DELAY`, `ATTACK_RANGE` de `Player` = 1 (multiplicateurs) ; les valeurs absolues vivent dans les armes.
- Chiffres de départ (spec) : carabine 8 dég. / 1,0 s / 500 ; PM 3 / 0,2 s / 350 ; fusil à pompe 6 × 5 plombs / 1,4 s / 260 / éventail 40° ; mitrailleuse 12 / 0,4 s / 600 ; lance-flammes 3 / 0,1 s / 180, perçant.
- Poids de tirage : mitrailleuse 0,3 ; autres armes 0,7 ; cartes de stats 1.
- Noms de fichiers et de classes en anglais ; ne jamais formater tout `EcranCarte` (fichier de Joël).
- Ordre : carabine → PM et mitrailleuse → cartes → fusil à pompe → lance-flammes en dernier.

## Review Focus

1. **Cible exactement sur Hugo** (distance 0) : aucune balle ne doit avoir une direction `NaN` → test « cible confondue » en Task 1.
2. **Arme déjà équipée** : sa carte ne doit jamais être proposée → test en Task 3.
3. **Moins de 3 cartes disponibles** : `pickRandom` renvoie ce qui reste, sans boucle infinie ni doublon → test en Task 3.
4. **Flamme qui reste sur un mob** : elle ne le touche qu'une fois → test `tryHit` en Task 5.
5. **Portée de visée** : `trouverMobLePlusProche` utilise la portée de l'arme, pas le multiplicateur (sinon Hugo ne tire plus jamais) → vérification manuelle en Task 1.
